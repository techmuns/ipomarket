## 3. Auto-selection of IPO #3 (sandbox preview — CI may differ)

Sandbox-run of `P-25b` resolved the §5.1 selection rule cleanly:

```json
{
  "slug": "m-r-maniveni-ipo",
  "url": "https://www.chittorgarh.com/ipo/m-r-maniveni-ipo/2627/",
  "status": "current",
  "reason": "current-open: list \"sme\" row date range \"22 - 26 May\" covers today",
  "date_text": "22 - 26 May",
  "source_list": "sme"
}
```

The selection uses the cached `phase-0/broker-pages/chittorgarh-list-rendered.html` + `chittorgarh-sme-rendered.html` (no re-fetch). When the operator dispatches the workflow, CI may resolve to a **different** IPO if Chittorgarh's list pages have changed in the meantime — that's expected and recorded by the probe.

**No operator input was required.** The auto-selection logic:
1. Reads both cached list HTML files.
2. Parses each `<tr>` row's slug + date range (handles same-month "22 - 26 May" and cross-month "30 Apr - 05 May" formats).
3. Skips OnEMI + Bagmane fixed slugs.
4. **Step 1**: pick the first row whose date range includes today's UTC date → `status: "current"`.
5. **Step 2 (fallback)**: pick the row with the largest end_date ≤ today → `status: "fallback"`.
6. If neither yields → `status: "none"`, status doc records the reason.

### 4.3 Chittorgarh-specific extras (additive on top of §10.3 patterns)

To improve precision against Chittorgarh's actual label conventions (observed in the cached `chittorgarh-detail-2-rendered.html` for OnEMI):

- **Date range fallback**: when no direct `"Open Date"` / `"Close Date"` label match, try the combined `"IPO Date"` / `"Bid Date"` cell and split a `"X to Y"` or `"X - Y"` range. Confidence: `medium` (still HIGH/MEDIUM gate). Open returns the start side; close returns the end side.
- **Registrar via `class="registrar-name"`**: OnEMI's page surfaces the registrar inside `<a class="registrar-name">Kfin Technologies Ltd. <contact info>`. Helper trims trailing contact text. Confidence: `medium`.

Both fallbacks return the source `method` string into `extracted-retuned.json` so the operator can see which strategy fired per field.
